# DREAM CAR V1.2 — 用户主页与信誉管理系统

你是一名资深全栈工程师、产品经理和 UI/UX 设计师。

请基于当前已完成的 DREAM CAR 拼车平台，新增用户主页、历史拼车记录、信誉积分、权限限制和申诉功能。

## 一、开发原则

1. 保留现有 V1.0 拼车、模拟付款、自动建群功能。
2. 保留 V1.1 国际物流、地址管理、到货检查及国内发货功能。
3. 不要重新创建项目，不要修改无关页面。
4. 沿用现有 React、TypeScript、Tailwind CSS 技术架构及视觉风格。
5. 使用现有数据存储方式，兼容历史数据。
6. 所有新增功能必须可交互，不能只生成静态页面。
7. 当前版本为本地演示，信誉分及权限控制不代表真实平台的安全认证。

## 二、公开用户主页

每位用户拥有独立的个人主页。

展示：
- 用户头像
- 昵称
- 所在省份
- 加入平台时间
- 信誉分及信誉等级
- 已完成发车次数
- 已完成参团次数
- 历史拼车记录

历史拼车记录区分「作为车主」和「作为车员」。

仅展示已完成或适合公开的拼车信息，包括活动名称、角色、完成时间和状态。

不公开真实姓名、手机号、详细地址、支付信息、个人国内物流单号。

在拼车详情页点击车主头像或昵称，可以进入车主主页。

## 三、个人中心

新增「我的信誉」入口。

展示：
- 当前信誉分
- 信誉等级
- 当前可使用权限
- 信誉分变动历史
- 每次加减分的原因、时间和关联车次
- 信誉规则说明
- 申诉入口

信誉分范围为 0–100，初始值为 100。

新用户应显示「暂无履约记录」，不能仅凭初始 100 分显示为已验证的可靠用户。

## 四、信誉等级及权限

暂按以下规则实现：

- 90–100 分：正常使用全部拼车功能。
- 70–89 分：正常使用，显示信誉提醒。
- 60–69 分：允许加入拼车，禁止发起新拼车。
- 0–59 分：禁止加入新拼车和发起新拼车。

信誉分低于阈值时，在相关页面展示限制原因及申诉入口。

权限校验必须实际生效：
- 发布拼车时检查用户信誉分。
- 加入拼车和模拟支付前检查用户信誉分。
- 不允许仅通过隐藏按钮实现权限限制。

被限制的用户仍然可以：
- 查看已有订单。
- 查看和处理现有群聊。
- 查看物流。
- 提交或修改未发货订单的地址。
- 处理已有订单的必要履约事项。
- 查看信誉记录并提交申诉。

## 五、信誉加分规则

车主完成一辆车的全部履约流程：+2 分。

车员正常完成一次拼车：+1 分。

同一车次同一用户只能获得一次对应奖励。

正常履约奖励每个自然月最多累计 +5 分。

信誉分最高为 100。

加分必须根据实际订单完成状态触发，不得仅凭点击按钮反复加分。

## 六、信誉扣分规则

以下事件需要经过模拟平台管理员核实后才能扣分：

- 车主无故取消已成团车次：-10 分。
- 车主无合理说明延迟发货：-5 分。
- 车员擅自退出已成团车次：-5 分。
- 提供虚假物流信息：-15 分。
- 严重欺诈、恶意骚扰等违规行为：根据具体违规类型扣除 20–40 分。

投诉提交后不立即扣分。

同一违规事件只能扣分一次。

所有扣分必须生成独立记录，包含：
- 事件 ID
- 关联用户
- 关联车次
- 违规类型
- 扣分数值
- 处理原因
- 处理时间
- 审核状态

## 七、投诉与申诉

用户可以针对关联拼车提交投诉。

投诉内容包括：
- 关联车次
- 被投诉用户
- 投诉类型
- 具体说明

投诉进入「待审核」状态。

用户受到扣分后，可以查看扣分原因并提交申诉。

申诉流程：
1. 用户查看处罚记录。
2. 提交申诉说明。
3. 模拟管理员审核。
4. 审核通过后撤销对应扣分。
5. 系统重新计算信誉分和用户权限。
6. 生成申诉结果通知。

不要允许车主直接修改车员信誉分。

## 八、模拟管理员后台

新增仅供演示使用的管理员模式。

支持：
- 查看待审核投诉。
- 查看违规事件。
- 确认或驳回违规。
- 查看申诉。
- 通过或驳回申诉。
- 查看信誉分变动记录。

管理员操作必须留下处理记录。

模拟管理员身份应与普通用户界面明确区分。

## 九、信誉数据管理

建议新增以下数据结构：

UserReputation：
- userId
- score
- level
- updatedAt

ReputationEvent：
- id
- userId
- carId
- eventType
- scoreChange
- reason
- createdAt
- status

Complaint：
- id
- reporterId
- targetUserId
- carId
- category
- description
- status
- createdAt

Appeal：
- id
- reputationEventId
- userId
- reason
- status
- reviewedAt

必须保证：
- 每次分数变化都有对应记录。
- 相同事件不能重复加减分。
- 申诉撤销扣分时不会产生重复恢复。
- 信誉分始终处于 0–100。
- 信誉等级和权限随分数变化同步更新。
- 页面刷新后数据仍然保留。
- 旧用户数据可以正常初始化信誉信息。

## 十、界面设计

保持 DREAM CAR 现有的视觉风格。

新增：
1. 公开用户主页。
2. 我的信誉页面。
3. 信誉规则说明。
4. 投诉与申诉页面。
5. 模拟管理员审核页面。

用户主页重点突出履约经历和信誉状态，不要让信誉分占据过多视觉空间。

信誉变动记录采用清晰的时间线或列表展示。

所有限制和处罚应明确展示原因。

## 十一、验收标准

开发完成后，必须能够演示：

1. 从拼车详情点击车主昵称，进入公开主页。
2. 查看车主和车员的历史拼车记录。
3. 在个人中心查看自己的信誉分。
4. 完成一笔模拟拼车履约后，获得相应加分。
5. 同一订单重复操作不会重复加分。
6. 提交投诉后，用户信誉分不会立即变化。
7. 模拟管理员确认违规后，系统执行扣分。
8. 信誉分低于 70 时，用户无法发布新拼车。
9. 信誉分低于 60 时，用户无法加入新拼车。
10. 被限制用户仍然可以处理已有订单和物流。
11. 用户可以针对处罚提交申诉。
12. 管理员通过申诉后，系统撤销扣分并重新计算权限。
13. 刷新网页后，信誉记录和处理状态仍然存在。
14. 原有拼车、群聊、物流和地址管理功能正常运行。

完成后说明新增功能、修改文件、测试结果及仍然属于模拟的部分。
