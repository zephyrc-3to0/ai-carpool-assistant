# 搭伴 · 追星周边拼车平台（MVP → V2.0 团体活动版）

一个帮助粉丝发起、寻找和加入偶像周边拼车的可运行网页项目。V2.0 在原有项目上增量升级：引入「团体 / 活动 / 活动商品」目录，把一级导航收敛为 **拼车广场 / 车主管理 / 消息 / 个人中心**，并把车主优先自购、整套凑套自动截团、普通拼邮满额自动截团、国际运费 AA 自动分摊、清关后地址收集、国内费用结算与异常处理补成完整闭环。数据全部保存在浏览器 `localStorage`，不依赖后端、不接入真实支付、物流、短信或身份认证服务。

## 运行

```bash
npm install
npm run dev
```

浏览器打开终端提示的地址（默认 `http://localhost:5173`）。

其他命令：

```bash
npm run build            # 类型检查 + 生产构建
npm run preview          # 预览构建产物
npm test                 # V1.1 物流与地址流程验收用例（69 项检查）
npm run test:reputation # V1.2 信誉与权限流程验收用例（73 项检查）
npm run test:share      # V1.3-A 商品与份额流程验收用例（85 项检查）
npm run test:v2         # V2.0 端到端与差异修复业务流程（113 项检查）
npm run test:ia         # V2.0 信息架构、双栏消息与旧逻辑修正（116 项检查）
npm run test:render     # 页面渲染冒烟测试（20 个页面）
npm run test:all        # 依次运行全部测试
```

## 技术栈

- React 18 + TypeScript
- Tailwind CSS 3（设计令牌集中在 `tailwind.config.js`）
- Vite 6
- Hash 路由，无需服务端 rewrite 配置

## V2.0 核心业务规则

### 车次状态

`招募中 recruiting → 已截团 cut → 采购履约中 purchasing → 已完成 completed`；招募截止但仍在平台最晚截团时间之前时进入 `招募已截止 expired` 等待车主处理，另有 `已流团 failed`。旧的 `pending_confirm / formed / ordered / closed` 在读取时自动迁移。

### 车主优先自购（不经过模拟付款）

- 车主在发布前可以勾选自购份额；发布后、截团前仍可追加剩余份额。
- 确认后**直接占位**，不生成订单、不产生任何模拟付款记录，单独保存为 `OwnerPurchase`。
- 自购份额计入招募进度、采购清单与国际运费分摊，但不计入车员人数、不产生车员信誉奖励。
- 已被车员付款占用的份额不会被覆盖；自购同样受活动限购与整车包裹容量约束。

### 占位时机

`选择份额 → 购买确认 → 模拟付款成功 → 生成有效订单 → 正式占位`。
付款前进入确认页不会永久占用库存；模拟付款失败 / 超时 / 主动取消都会释放预留。车主不能进入模拟付款链路（`reserveSlotsOp` / `confirmOrderOp` 均直接拒绝）。

### 截团

| 模式 | 条件 | 处理 |
| --- | --- | --- |
| 整套凑套 | 全部开放成员位置被有效占用 | 系统自动截团 |
| 普通拼邮 | 未达最低金额、包裹未满 | 继续招募 |
| 普通拼邮 | 已达最低金额、包裹未满 | 车主可手动截团 |
| 普通拼邮 | 已达最低金额、包裹满额 | 系统自动截团 |
| 普通拼邮 | 未达最低金额、包裹满额 | 停止新增购买，按未成团规则处理 |

成团金额与包裹容量统计都包含车主自购。普通拼邮的整车容量是**全局**上限，多个商品共享同一份容量，不会因为选了多个商品而放大。

### 延期与流团

- 车主自设的招募截止到达但仍早于平台最晚截团时间时，车次进入「招募已截止」，等待车主选择延期或流团。
- 未成团时车主可在允许期限内延期，延期不得超过「官方下单截止 − 最低采购预留时间（1 小时，可配置）」，并通知已参与车员。
- 到达平台最晚截团时间仍未成团时自动流团；数据加载时会立即扫描，页面打开期间每分钟复查，避免关闭浏览器期间过期的车次无限停留在招募中。
- 流团时只对**真实存在的模拟支付记录**生成退款；车主自购不产生退款交易，重复扫描不会重复退款。
- 已截团、采购履约中、已完成和已流团车次不会被截止扫描改写。

### 国际运费 AA

- 整车国际运费在**发布时**一次确定，截团后不再录入。
- 截团时按最终有效份数（成员位置份数或商品件数）自动分摊，车主自购同时计入分子分母。
- 所有金额以「分」为单位的整数运算；尾差策略为独立可替换接口（`src/lib/money.ts`），当前实现保证分摊合计恒等于整车国际运费总额。
- 车主本人的分摊只做记账（账单状态 `booked`），不产生向自己的模拟付款。
- 国际运费未全员支付**不阻止**车主上传采购凭证并继续采购，未付账单保持待支付。

### 采购凭证

- 截团后车主可上传纯文字凭证，或从本地选择 JPG / PNG 等图片作为附件；历史纯文字记录继续兼容。
- 图片在浏览器本地缩放至最长边 1024px 并转为 JPEG，单张 data URL 限制约 400KB，全部凭证图片合计限制约 1.2MB，为订单、聊天和物流数据预留 localStorage 空间。
- 管理页展示图片缩略图并可查看大图；若图片超限或本地图片空间已满，会阻止附件写入并提示改用更小图片或纯文字凭证。
- localStorage 写入仍有异常保护，存储配额错误不会导致页面崩溃。

### 国内费用与发货

- 国际包裹**清关完成后**（状态进入「国内运输中」及以后）自动开启地址收集并通知车员。
- 车主按车员登记打包费与国内运费 → 车员在参与订单详情完成模拟支付 → 车主逐车员独立发货（不要求整车一起完成）。
- 车员对费用有异议时可发起费用异议，账单转为「存在异议」并进入单车异常处理中心，车主处理后恢复为待支付。
- 未提交有效地址、未支付国内费用或存在未处理异议时，不能标记为已发货。

### 消息与群聊

- 首位车员付款成功占位后自动建群；同车再次加购不重复建群、不重复建立参与关系。
- 消息中心固定置顶系统通知、物流消息、申诉助手；桌面端左侧群聊列表与右侧当前会话并列，切换时直接复用 `ChatPage`，聊天记录仍保存在同一个 `Chat` 数据模型中。
- `/chat/:id` 独立群聊路由继续保留，已有链接不会失效。
- 不提供一对一私聊，也不允许用户自由创建群聊。

## 数据模型（V2.0 新增）

| 类型 | 含义 | 关键约束 |
| --- | --- | --- |
| `ArtistGroup` | 艺人团体目录 | 团体是活动与商品的上级归属 |
| `EventInfo` | 活动目录 | 包含官方下单截止时间；最晚允许截团时间 = 截止 − 预留时间 |
| `EventProduct` | 活动商品目录 | 含类别、规格、单价、每人限购件数与可开放成员位置 |
| `OwnerPurchase` | 车主自购记录 | 不产生模拟付款；与车员订单完全分离 |
| `PaymentRecord` | 模拟支付 / 退款记录 | 金额以「分」存储；`goods / freight / domestic / refund` |
| `FreightBill` | 国际运费账单 | `pending` 车员待付 / `paid` 车员已付 / `booked` 车主自担记账 |
| `DomesticFeeBill` | 国内费用账单 | 打包费 + 国内运费；`pending / paid / disputed` |
| `Participation` | 车次参与关系 | 同一用户同一车次只建立一份 |
| `PurchaseVoucher` | 官方下单凭证 | 车主上传，同时记录采购状态推进；可选保存已压缩的本地图片附件，纯文字历史记录继续兼容 |
| `ExceptionRecord` | 异常处理记录 | 订单 / 采购 / 费用 / 物流四类；辅助功能，不是必经阶段 |
| `EventSubmission` | 活动收录申请 | 审核通过后由用户手动发布草稿 |
| `CarpoolDraft` | 拼车草稿 | 统一在车主管理中查看与继续编辑 |

`Carpool` 新增可选字段：`groupId` / `eventId` / `orderDeadline` / `internationalFreightCents` / `minAmountCents` / `maxPackageItems` / `cutAt` / `extensions` / `freightRemainderStrategy` / `requiresDomesticFee`。

**旧数据兼容**：数据结构版本为 `7`。`normalizeData()` 在读取时补齐全部 V2.0 集合、旧状态迁移、车主运费账单标记为记账；存量车次保留 legacy 平铺结构与原有物流 / 地址 / 信誉 / 群聊数据，不会因升级而改变既有履约规则（旧车次不走国内费用结算流程）。

## 统一配置

`src/config.ts` 集中存放平台配置，避免多处硬编码：

- `MIN_RESERVE_HOURS = 1`：最低采购预留时间（小时）。
- `FREIGHT_REMAINDER_STRATEGY`：国际运费尾差策略 ID。
- `MAX_OPEN_ITEMS = 24`：单车最多开放商品数。
- `PACKAGE_ITEMS_RANGE`：整车包裹件数允许区间。

## 状态定义

- 车次状态：`招募中 → 已截团 → 采购履约中 → 已完成`；招募截止待车主处理时为 `招募已截止`，另有 `已流团`。
- 国际物流：`等待发货 → 国际运输中 → 清关 / 转运中 → 国内运输中 → 车主已签收 → 到货检查完成`。
- 收货地址状态：`待填写 / 已提交 / 逾期未提交`。
- 国内发货状态：`待填写地址 → 待打包 → 待发货 → 已发货 → 已签收`。

## 模拟账号

右上角头像可切换四个模拟账号，用于体验不同身份：

- 汽水小鹿（默认）
- 椰子青
- 九九云
- 薄荷糖

同一个账号既是车主也是车员；车主不能加入自己发起的拼车。切换账号即可体验「发布 → 自购 → 认领 → 付款占位 → 截团 → 采购凭证 → 国际物流 → 清关 → 地址收集 → 国内费用 → 独立发货 → 确认收货」的多角色流程。

## 数据与重置

数据保存在 `localStorage` 的 `daban-carpool-mvp-v1` 键下，刷新后保留。需要恢复初始演示数据时，在浏览器控制台执行：

```js
localStorage.removeItem('daban-carpool-mvp-v1')
location.reload()
```

## 说明与限制

- 预置的团体、活动、商品与拼车均为课程演示数据，不代表真实活动信息；所有商品款、国际运费、国内费用与退款均为**模拟交易**，不接入真实支付渠道。
- 物流公司、单号与节点全部由车主手动录入，未接入真实物流查询接口；「已签收」同样由车主手动更新。
- 库存预留、占位与截团校验全部在浏览器本地完成。「预留超时」由页面上的演示选项触发，不会真正等待 10 分钟；本地演示中的状态检查**不等于**生产环境中的并发安全库存事务，不宣称已实现跨设备原子并发保护。
- 演示数据使用虚构的姓名、电话与地址，不要求输入真实个人信息。
- 账号切换、地址归属、信誉分、权限限制、投诉申诉与管理员模式均用于本地演示，**不构成真实的数据隔离、安全保护、身份认证或平台信用评价**。
