# 搭伴 · 追星周边拼车平台（MVP + V1.1 物流地址 + V1.2 用户信誉）

一个帮助粉丝发起、寻找和加入偶像周边拼车的可运行网页项目。V1.2 新增公开用户主页、历史履约记录、信誉积分与权限限制、投诉申诉以及模拟管理员审核。数据全部保存在浏览器 `localStorage`，不依赖后端、不接入真实支付、物流、短信或身份认证服务。

## 运行

```bash
npm install
npm run dev
```

浏览器打开终端提示的地址（默认 `http://localhost:5173`）。

其他命令：

```bash
npm run build            # 类型检查 + 生产构建
npm run preview          # 预览构建产物
npm test                 # V1.1 物流与地址流程验收用例（62 项检查）
npm run test:reputation # V1.2 信誉与权限流程验收用例（73 项检查）
npm run test:render     # V1.1 / V1.2 新增页面渲染冒烟测试（11 个页面）
npm run test:all        # 依次运行全部测试
```

## 技术栈

- React 18 + TypeScript
- Tailwind CSS 3（设计令牌集中在 `tailwind.config.js`）
- Vite 6
- Hash 路由，无需服务端 rewrite 配置

## 页面与流程

### V1.0 基础流程

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 拼车广场 | 搜索、按商品 / 成员位置筛选、查看剩余位置 |
| `/create` | 发起拼车 | 表单校验 + 实时预览，发布后进入详情页 |
| `/detail/:id` | 拼车详情 | 选择空余位置 → 进入模拟支付 |
| `/pay/:id?slots=` | 模拟支付 | 费用明细，确认后锁定位置并生成订单 |
| `/mine` | 我的拼车 | 我加入的 / 我发起的 |
| `/manage`、`/manage/:id` | 车主管理 | 车员名单、位置占用、进度、确认拼成 |
| `/chat/:id` | 拼车群聊 | 成员列表、群昵称与公告（车主可改）、文字消息 |

### V1.1 物流追踪与地址管理

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/profile` | 个人中心 | 账号信息、我的地址 / 站内通知 / 我的拼车入口 |
| `/addresses` | 我的地址 | 地址簿增删改查、设置默认地址、地址标签、删除二次确认 |

| `/shipping/address/:id` | 车员填写收货地址 | 使用已保存地址 / 填写临时地址（可选同时保存到地址簿） |

### V1.2 用户主页与信誉管理

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/user/:userId` | 公开用户主页 | 头像、昵称、省份、加入时间、信誉状态、完成次数及车主 / 车员历史记录 |
| `/reputation` | 我的信誉 | 当前分数与等级、可用权限、信誉分变动时间线、扣分申诉入口 |
| `/reputation/rules` | 信誉规则 | 等级权限、履约加分、违规扣分及投诉申诉流程 |
| `/complaints` | 投诉与申诉 | 针对关联车次投诉成员、查看投诉进度、针对生效扣分提交申诉 |
| `/admin` | 模拟管理员后台 | 审核投诉与申诉、查看违规事件、信誉记录及管理员操作日志 |

信誉规则：

- `90–100`：可正常使用全部拼车功能。
- `70–89`：可正常使用，页面显示信誉提醒。
- `60–69`：可以加入拼车，但不能发起新的拼车。
- `0–59`：不能加入或发起新的拼车，但已有订单、群聊、物流与地址履约流程不受影响。
- 车主完成整车履约 `+2`，车员确认收货完成一次拼车 `+1`；同一车次只奖励一次，每个自然月正常履约奖励最多 `+5`。
- 投诉提交后不会立即扣分；只有模拟管理员确认违规才生成扣分记录。申诉通过后对应扣分被撤销，系统重新计算分数与权限。

V1.2 履约闭环：

```
车员收到国内包裹 → 在物流页确认收货 → 订单标记为已完成 → 车员获得履约奖励
→ 所有车员均已确认收货 → 车主在车次管理确认整车履约完成 → 车主获得履约奖励
```

「车主点击已发货」不会直接被视为交易完成。

完整闭环：

```
车主发布拼车 → 车员选择位置 → 模拟支付 → 加入拼车 → 车主确认拼成 → 自动建群
→ 车主录入国际物流 → 状态更新为「国际运输中」→ 自动开启地址收集 → 车员收到提醒
→ 车员提交收货地址 → 车主查看收集进度并催促未提交者
→ 车主签收并完成到货检查（未提交者标记逾期，仍可补交）
→ 车主逐个录入国内快递公司与单号 → 车员收到发货通知 → 查看自己的国内物流
```

## 数据模型（V1.1 / V1.2 新增）

| 类型 | 含义 | 关键约束 |
| --- | --- | --- |
| `SavedAddress` | 用户个人地址簿 | 按 `userId` 隔离，同一用户只有一个默认地址 |
| `OrderShippingAddress` | 拼车订单的收货地址快照 | 与地址簿独立存储，修改 / 删除地址簿不会影响已提交订单 |
| `InternationalShipment` | 车次共享国际物流 | 一个车次一份，所有车员查看同一份，仅车主可改 |
| `DomesticShipment` | 车员个人国内物流 | 同一车次不同车员的记录相互独立 |
| `Notification` | 站内通知 | 包含物流、地址、扣分、投诉与申诉结果通知 |
| `UserReputation` | 用户当前信誉档案 | 分数始终为 0–100，等级和权限随分数同步变化 |
| `ReputationEvent` | 每次信誉分变动 | 同一车次 / 用户 / 类型只记录一次，撤销后不重复恢复 |
| `Complaint` | 用户投诉 | 提交后待审核，管理员确认违规后才会扣分 |
| `Appeal` | 扣分申诉 | 每条扣分记录只能申诉一次，通过后撤销对应事件 |
| `AdminActionLog` | 管理员操作日志 | 记录投诉、申诉和信誉处理动作 |

原有 `Carpool` 新增可选字段 `addressCollection` 与 `fulfilledAt`；`Order` 新增可选字段 `fulfillmentStatus` 与 `fulfilledAt`。

### 状态定义

- 国际物流：`等待发货 → 国际运输中 → 清关 / 转运中 → 国内运输中 → 车主已签收 → 到货检查完成`
- 收货地址状态：`待填写 / 已提交 / 逾期未提交`
- 国内发货状态：`待填写地址 → 待打包 → 待发货 → 已发货 → 已签收`

### 状态迁移逻辑

`src/lib/logisticsOps.ts` 存放 V1.1 物流地址的纯状态迁移函数；`src/lib/reputationOps.ts` 存放 V1.2 履约奖励、投诉、违规扣分、申诉撤销与权限校验逻辑；`src/store.tsx` 负责调用与持久化，因此两套业务流程都可以直接进行单元测试。

## 模拟账号

右上角头像可切换四个模拟账号，用于体验不同身份：

- 汽水小鹿（默认，当前为车员视角）
- 椰子青
- 九九云
- 薄荷糖

同一个账号既是车主也是车员；车主不能加入自己发起的拼车。切换账号即可体验「车主录物流 → 车员填地址 → 车主发货 → 车员查看物流」的多角色流程。

## 数据与重置

数据保存在 `localStorage` 的 `daban-carpool-mvp-v1` 键下，刷新后保留。数据结构版本为 `3`：V1 / V1.1 存量数据在读取时会自动补齐 V1.2 信誉、投诉、申诉与管理员日志集合，老用户默认初始化为 100 分且显示「暂无履约记录」，原有拼车、订单、群聊、物流与地址数据不受影响。

需要恢复初始演示数据时，在浏览器控制台执行：

```js
localStorage.removeItem('daban-carpool-mvp-v1')
location.reload()
```

## 说明与限制

- 预置的 NCT DREAM 相关拼车、订单与群聊均为课程演示数据，不代表真实活动信息；支付流程为本地模拟，不会产生真实交易。
- 物流公司、单号与节点全部由车主手动录入，未接入真实物流查询接口；「已签收」同样由车主手动更新，不会伪装成快递公司的自动同步。
- 演示数据使用虚构的姓名、电话与地址，不要求输入真实个人信息。
- 账号切换、地址归属、信誉分、权限限制、投诉申诉与管理员模式均用于本地演示，**不构成真实的数据隔离、安全保护、身份认证或平台信用评价**；所有数据都保存在同一台机器的浏览器里。
