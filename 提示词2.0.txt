# DREAM CAR V2.0 — 基于现有项目的完整功能升级指令

你是一名资深全栈工程师、产品经理和 UI/UX 设计师。

请基于**当前已经开发完成的 DREAM CAR 拼车平台**，按照以下需求将项目升级至 V2.0。

**本次任务是对现有项目进行功能修改、业务逻辑修正和页面重组，不是重新创建一个项目。**

请优先复用现有的 React、TypeScript、Tailwind CSS 技术架构、组件、页面、数据模型和存储机制。

## 一、开发原则与执行要求

### 1.1 必须遵守的原则

1. 不重新创建项目，不删除原有项目数据。
2. 不随意修改无关页面，不进行无需求依据的视觉重设计。
3. 保留已有的拼车发布、商品认领、模拟支付、自动建群、国际物流、国内发货、用户主页、信誉积分和申诉等功能，但需要根据 V2.0 规则进行调整。
4. 所有新增或修改功能必须具有真实的前端交互及状态更新，不能只是静态页面。
5. 不连接真实支付渠道，所有商品款、国际运费、国内费用及退款均为模拟交易。
6. 同一个业务规则必须在不同页面表现一致，避免拼车详情、车主管理、订单详情显示不同数据。
7. 不得擅自增加尚未确定的业务规则，例如允许车员自由取消订单、复杂商品分套编号、独立库存仓储系统、额外收费项目等。
8. 采用可维护的数据结构和组件设计，避免将复杂业务判断直接散落在各个页面。
9. 当前版本为产品演示系统，不得将模拟信誉分或模拟支付包装成真实的交易安全保障。

### 1.2 开始开发前，先检查现有项目

请首先检查：

- 当前路由和导航结构
- 已实现页面和组件
- 拼车、商品、用户、订单、群聊、物流、费用、信誉、申诉相关的数据结构
- localStorage 或当前实际使用的持久化机制
- 已有业务状态和状态流转逻辑
- 现有代码中已经实现但与 V2.0 冲突的功能

形成内部的修改清单：

**保留、修改、新增、删除。**

对于已经满足需求的功能直接复用，不重复开发。

对旧版本数据进行兼容处理，必要时实现版本迁移，避免已有演示数据因字段变化而导致页面报错。

如果缺少实现某项规则所必需的业务信息，不得自行发明规则；应先保持现有可用能力，并明确列出待确认的问题。

# 二、全站信息架构升级

将一级导航统一调整为四个模块：

1. 拼车广场
2. 车主管理
3. 消息
4. 个人中心

桌面端保持统一导航结构、视觉风格和页面交互模式。

## 2.1 拼车广场

### 首页

展示：

- 近期热门活动轮播 Banner
- 艺人团体目录
- 团体搜索入口

Banner 可以直接跳转到对应团体的指定活动页面。

### 团体与活动页面

采用左右结构：

**左侧：** 当前团体的活动列表。

**右侧：** 当前选中活动的拼车广场。

拼车列表包含：

- 车主头像和昵称
- 车主所在省份
- 拼车标题
- 拼车模式
- 招募进度
- 招募截止时间
- 当前车次状态

### 筛选与排序

支持：

- 发布时间排序
- 招募进度排序
- 省份多选
- 成员位置多选
- 商品类别多选

同一筛选维度内多个选项采用 OR 逻辑，不同筛选维度之间采用 AND 逻辑。

筛选和排序必须真正影响列表展示结果。

### 发车入口

只能在具体活动页面中发起对应活动的拼车。

不得允许用户绕过活动选择，直接创建缺少团体或活动信息的车次。

# 三、发布拼车页面升级

将发布拼车整理为单页六个业务分区。

## 3.1 基本信息

包含：

- 已选团体
- 已选活动
- 拼车标题
- 拼车说明
- 拼车模式

拼车模式分为：

**整套凑套、普通拼邮。**

团体和活动应由当前活动页面传入，不允许用户随意更换为与当前上下文不一致的对象。

## 3.2 商品与开放数量

商品来自平台活动商品目录。

支持同一辆车选择多个商品。

### 整套凑套

车主为商品设置开放成员位置和对应数量。

例如：

- A 版 MARK：2 份
- A 版 JENO：1 份
- B 版 JAEMIN：2 份

同一商品的同一成员可以开放多份。

不创建复杂的“第一套、第二套”编号系统，不按照每套独立截团。

### 普通拼邮

车主选择可购买商品，同时设置：

- 最低成团金额
- 整车国际包裹最大商品件数

不设置最高购买金额。

商品本身的活动限购规则仍需遵守。

## 3.3 车主优先自购

**这是 V2.0 的重要修改。**

车主在正式发布前可以优先选择自己要购买的商品或成员位置。

这些份额：

- 不需要模拟付款
- 由车主确认后直接占位
- 计入整体招募进度
- 计入最终采购清单
- 计入国际运费 AA 分摊

必须保存独立的车主自购记录，不得伪造车主向自己付款的模拟交易。

正式发布后、截团前，车主仍然可以追加自购剩余份额。

但不得覆盖已经由车员成功付款占用的份额。

## 3.4 费用设置

车主在发布时填写**整车国际运费总额**。

国际运费是发车时确定的费用，不需要截团后再次录入。

同时展示国际运费 AA 分摊规则：

- 整套凑套：按成员位置份数均摊
- 普通拼邮：按商品件数均摊

车主自购部分也参与分摊。

每份商品或成员位置的国际运费权重相同。

由于最终参与数量尚未确定，发布阶段不需要提前计算个人应付国际运费。

国内打包费和国内运费在后续发货阶段分别结算。

## 3.5 招募时间

展示官方下单截止时间。

平台暂时统一设置：

**最低采购预留时间：1 小时。**

最晚允许截团时间 = 官方下单截止时间 − 1 小时。

车主设置的招募截止时间不得晚于最晚允许截团时间。

这个 1 小时应作为可修改的统一配置项，不要写死在多个页面中。

## 3.6 预览、草稿与发布

保留：

- 保存草稿
- 预览拼车
- 正式发布

草稿统一在车主管理中查看。

如果活动未收录，允许用户提交活动收录申请；审核通过后由用户手动发布草稿。

发布成功后，拼车应立即出现在对应活动广场。

# 四、拼车详情与购买流程

## 4.1 拼车详情

采用左右双栏结构。

左侧展示车主信息、车次进度、商品列表、招募规则、费用说明及物流信息。

右侧为固定的选购区域。

允许车员：

- 选择多个不同成员位置
- 选择同一成员的多份
- 购买多种不同商品
- 在未截团时再次加购

购买数量不能超过当前剩余份额及活动限制。

## 4.2 正式占位时机

必须使用以下逻辑：

**选择商品 → 购买确认 → 模拟付款成功 → 生成有效订单 → 正式占位。**

仅加入选购区域或者进入确认页，不得永久占用库存。

模拟付款失败时：

- 不生成有效购买订单
- 不正式占用份额
- 不修改既有成功订单

需要保证商品剩余数量和招募进度保持一致。

## 4.3 购买确认页

独立页面展示：

- 商品名称和规格
- 成员位置
- 数量
- 商品款合计
- 国际运费后续 AA 提示
- 招募及交易规则
- 模拟付款操作

首次购买只支付商品款。

不得在首次购买时要求车员填写国内收货地址。

## 4.4 同车多次加购

同一用户在同一车次下：

- 只建立一份参与关系
- 可以拥有多笔独立购买记录
- 商品总数在参与详情中聚合展示
- 原始购买时间、商品和模拟付款信息分别保存
- 不重复创建群聊

## 4.5 取消订单限制

成功付款后的订单不允许车员主动取消。

不得提供自由退出拼车、主动申请取消或车主随意批准取消等常规交易操作。

未成团、缺货、采购失败等导致的退款，进入异常处理流程。

# 五、截团、延期与流团规则

## 5.1 整套凑套

当全部开放成员位置均被有效占用时，系统立即自动截团。

有效占用包含：

- 车员模拟付款成功的份额
- 车主已确认的自购份额

不需要车主手动截团。

截团后不得新增认领。

## 5.2 普通拼邮

普通拼邮采用以下规则：

| 条件 | 处理 |
|---|---|
| 未达最低金额，包裹未满 | 继续招募 |
| 已达最低金额，包裹未满 | 车主可手动截团 |
| 已达最低金额，包裹满额 | 系统自动截团 |
| 未达最低金额，包裹满额 | 停止新增购买，按未成团规则处理 |

成团金额统计包含车主自购商品的金额。

包裹容量统计包含车主与车员的全部有效购买件数。

不得超出包裹最大商品件数。

## 5.3 招募截止与延期

未成团时：

- 车主可以在允许期限内选择延期
- 延期不得超过平台最晚截团时间
- 需要向已参与车员发送通知
- 未延期或达到最晚截团时间仍未成团时，进入流团退款

流团时，对车员已经实际模拟支付的商品款生成模拟退款记录。

车主自购不产生退款交易。

# 六、国际运费 AA 自动结算

**这是必须重点修正的旧版本逻辑。**

## 6.1 费用确定时机

整车国际运费在发布拼车时就已经填写。

车主不需要在截团后重新填写国际运费。

## 6.2 截团时自动计算

截团后锁定最终有效购买数量。

整套凑套：

个人应付国际运费 = 整车国际运费总额 × 个人有效成员位置份数 ÷ 整车有效成员位置总份数。

普通拼邮：

个人应付国际运费 = 整车国际运费总额 × 个人有效商品件数 ÷ 整车有效商品总件数。

车主自购份额计入分母和车主本人分摊金额。

系统需要保证所有人的分摊金额合计等于整车国际运费总额。

货币计算不得直接依赖可能产生浮点误差的简单小数累加。

具体尾差归属策略尚未确定，应采用独立、可替换的计算策略，不要把某一种归属方式作为不可修改的产品规则。

## 6.3 支付与状态

截团后：

- 系统生成每位车员的国际运费账单
- 发送系统通知
- 车员在个人订单详情中查看并模拟支付
- 车主可查看未支付和已支付名单
- 车主本人分摊金额只进行记账，不产生向自己的模拟付款

**国际运费未全员支付，不阻止车主开始采购。**

不得因为车员未支付国际运费，就自动取消其商品订单。

# 七、车主管理模块重组

将车主管理作为独立一级导航。

## 7.1 我的车次

展示车主发布的所有车次：

- 草稿
- 招募中
- 已截团
- 采购履约中
- 已完成
- 已流团

点击进入对应车次的管理空间。

## 7.2 车次概况

展示：

- 车次当前状态
- 招募进度
- 成团与截团情况
- 待处理任务
- 最新动态
- 车员和订单列表入口
- 采购管理入口
- 物流与发货入口
- 异常处理入口

不再单独创建复杂的招募管理页面。

招募期业务操作应通过现有拼车详情的车主视角完成。

## 7.3 采购管理

截团后自动生成采购商品清单。

必须正确合并：

- 车员购买的商品
- 车主自购的商品

展示每种商品的最终采购数量。

允许车主上传官方下单凭证，并记录采购状态。

不新增复杂的仓储盘点、批次匹配和多包裹采购系统。

## 7.4 物流与发货管理

统一管理：

- 国际物流状态
- 国际运费结算状态
- 到货商品检查
- 国内地址收集
- 国内费用登记
- 国内发货

默认一辆车对应一个国际物流订单。

车主只需更新整车国际运输信息，不必逐件填写国际物流。

## 7.5 国内地址收集

在国际包裹清关完成后启动地址收集。

系统自动通知已参与车员。

车员在「我参与的 → 参与订单详情」提交本次订单的收货地址。

车主可以查看尚未提交的用户，并手动发送提醒。

个人中心的「地址管理」只负责保存、编辑、删除及设置默认地址。

**不要在地址管理页面加入订单列表、物流管理或车次绑定模块。**

## 7.6 国内费用与发货

车主按车员登记：

- 打包费
- 国内运费

车员查看费用后完成模拟支付。

如果车员认为费用异常，可以发起异议，进入异常处理。

允许不同车员独立完成国内履约。

不需要等待整车所有人都完成地址提交和费用支付后才统一发货。

发货后记录国内快递信息。

车员可以查看物流、确认收货。

在既定自动确认期限内无未解决异常的订单，可按规则自动完成。

期限尚未确定，不得编造固定天数。

## 7.7 异常处理中心

作为单车管理中的辅助功能。

展示订单异常、采购异常、费用异议、物流异常等事项。

不将异常处理设计成所有车次必须经历的正常履约阶段。

# 十、数据与业务逻辑要求

请根据现有代码结构调整数据模型，避免重复或相互矛盾的状态字段。

至少需要明确表示：

- 用户
- 团体与活动
- 活动商品
- 拼车车次
- 车次开放商品与成员位置
- 车主自购记录
- 车员购买订单
- 车次参与关系
- 国际运费账单
- 国内费用账单
- 模拟支付与退款记录
- 采购凭证
- 物流信息
- 收货地址
- 群聊及消息
- 异常处理记录
- 信誉与申诉记录

### 数据一致性要求

1. 商品剩余数量必须由有效购买和自购占用准确计算。
2. 成团进度与采购清单使用同一套有效购买数据。
3. 车主自购不得被统计成车员模拟付款收入。
4. 国际运费按截团后的最终有效数量计算。
5. 同车多次加购不能产生重复参与关系和重复群聊。
6. 单个车员的国内发货状态与整车国际物流状态分开管理。
7. 流团退款只能针对真实存在的模拟支付记录。
8. 旧版本数据迁移后仍应能够正常查看。
9. 模拟付款、占位和截团判断必须避免连续点击或重复提交造成的重复订单与超卖。

# 十三、验收测试

至少完成以下场景：

**场景 1：整套凑套**

车主发布 → 优先自购 → 车员认领 → 付款成功占位 → 车主追加自购补齐 → 自动截团 → 生成采购清单 → 自动计算国际运费。

**场景 2：普通拼邮主动截团**

车主设置最低金额与包裹件数 → 用户购买 → 满足最低金额但未满件数 → 车主主动截团 → 费用计算正确。

**场景 3：普通拼邮满额自动截团**

购买金额达到最低要求，商品数量达到包裹上限 → 系统自动截团 → 禁止新增购买。

**场景 4：再次加购**

同一车员成功购买后再次加购 → 保留两笔交易记录 → 正确合并商品数量 → 只有一个参与关系和一个群聊。

**场景 5：延期与流团**

到达招募截止仍未成团 → 延期或流团 → 流团时生成准确的模拟退款记录 → 不向车主自购生成退款。

**场景 6：国际运费 AA**

发布时填写国际运费 → 截团后按有效单位 AA → 包含车主自购 → 分摊总额准确 → 车员支付状态更新。

**场景 7：部分国际运费未支付**

部分车员未结算国际运费 → 车主仍可上传官方采购凭证并继续采购管理 → 未付账单保持待支付状态。

**场景 8：国内发货**

国际包裹清关完成 → 通知车员提交地址 → 车主录入国内费用 → 车员完成支付 → 车主分别发货 → 车员确认收货。

**场景 9：权限与数据安全**

普通车员不能修改车主的采购和物流管理信息；公开主页不显示个人收货地址；不可超卖商品；刷新页面后记录保持一致。
