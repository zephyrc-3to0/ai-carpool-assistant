# DREAM CAR V1.1 — 物流追踪与地址管理模块

你是一名资深全栈工程师、产品经理和 UI/UX 设计师。

请基于当前已经开发完成的 DREAM CAR 追星周边拼车平台，进行 V1.1 增量开发。

## 一、开发原则

1. 保留当前所有已经实现的页面、功能、交互和数据。
2. 不要重新创建项目，不要重构与本次需求无关的模块。
3. 首先检查现有项目的技术架构、数据结构和状态管理方式，再进行修改。
4. 沿用现有网页的视觉设计、组件风格、导航方式和交互习惯。
5. 只增加物流追踪、地址管理、到货检查和国内发货功能。
6. 继续使用现有项目的数据存储方案。若当前使用 localStorage，则继续使用，并做好数据兼容。
7. 所有新增功能必须可以实际操作，不能只有静态界面。
8. 暂不接入真实物流 API、短信服务和支付接口。
9. 所有物流节点、通知和发货信息使用模拟数据或车主手动录入。
10. 不要自行扩展本次需求之外的功能。

## 二、完整业务流程

现有业务流程：

车主发布拼车 → 车员选择位置 → 模拟支付 → 加入拼车 → 车主确认拼成 → 系统自动建群。

在此基础上新增：

车主完成官方下单 → 国际物流开始 → 全体车员查看国际物流 → 系统提醒车员补充收货地址 → 车主收到国际包裹并完成检查 → 车主打包、录入国内物流 → 车员查看个人物流信息。

国际物流追踪与地址收集应当并行进行。

## 三、模块一：国际物流追踪

### 1. 车主端

在已经拼成的车次管理页面中，新增「物流管理」入口。

车主可以：
- 填写国际物流公司。
- 填写国际物流单号。
- 填写物流查询链接（可选）。
- 手动更新国际物流状态。
- 填写物流状态说明。
- 记录物流状态更新时间。

国际物流状态包括：
1. 等待发货
2. 国际运输中
3. 清关 / 转运中
4. 国内运输中
5. 车主已签收
6. 到货检查完成

车主修改状态后，保存到当前车次的数据中。

### 2. 车员端

在「我的拼车」和车次详情中增加国际物流查看入口。

同一车次的所有车员都能查看：
- 国际物流公司
- 国际物流单号
- 物流查询链接
- 当前物流状态
- 物流更新时间
- 物流进度时间线

所有车员查看的是同一份国际物流信息。

国际物流信息只能由对应车主修改。

### 3. 地址收集触发

当车主首次将国际物流状态更新为「国际运输中」或后续运输状态时：

- 系统自动开启该车次的地址收集。
- 为所有已确认加入该车次的车员生成站内提醒。
- 在车员的「我的拼车」中展示「待补充收货地址」提示。
- 提供「填写收货地址」按钮。

同一车次不得因为车主重复修改物流状态而重复创建相同的地址收集任务。

## 四、模块二：个人地址管理

在个人中心新增「我的地址」页面。

### 1. 地址管理功能

用户可以：
- 新增地址。
- 查看已保存地址。
- 编辑地址。
- 删除地址。
- 设置默认地址。
- 添加地址标签，例如「学校」「家」「宿舍」。

每条地址包含：
- 地址 ID
- 所属用户 ID
- 地址标签
- 收件人姓名
- 联系电话
- 省份
- 城市
- 区县
- 详细地址
- 是否默认地址

### 2. 地址管理规则

- 同一用户可以保存多个地址。
- 同一用户最多只有一个默认地址。
- 设置新的默认地址时，自动取消原默认地址。
- 删除默认地址后，允许用户重新设置默认地址。
- 用户只能管理自己的地址。
- 不同模拟账号之间的地址不能混用。
- 删除地址需要二次确认。
- 所有地址数据在页面刷新后仍然保留。

## 五、模块三：车员补充收货地址

当车次开启地址收集后，车员可以进入地址填写页面。

提供两种方式。

### 方式 A：使用已保存地址

展示当前账号的地址簿。

用户可以：
- 查看所有已保存地址。
- 选择其中一个地址。
- 默认优先展示默认地址。
- 确认将该地址用于本次拼车。

### 方式 B：填写临时地址

用户可以手动填写：
- 收件人姓名
- 联系电话
- 省市区
- 详细地址

提供复选框：

「同时保存到我的地址簿」

如果勾选，提交时将该地址新增到个人地址簿。

如果未勾选，只保存到本次拼车订单中。

### 重要数据规则

个人地址簿与拼车订单收货地址必须独立存储。

提交地址时，应将完整地址信息复制为当前订单的地址快照。

后续修改或删除个人地址簿中的地址，不得自动改变已经提交的拼车订单地址。

车员修改当前订单地址，也不得自动修改个人地址簿。

## 六、模块四：地址收集进度

### 1. 车主端

在车次物流管理页面新增「地址收集」模块。

展示：
- 当前车次车员总数
- 已提交地址人数
- 未提交地址人数
- 每位车员的地址提交状态

车主可以查看本车次车员提交的收货信息。

对未提交地址的车员，提供「催促填写」按钮。

点击后：
- 向对应车员发送一条站内通知。
- 记录催促时间。
- 在车员账号中展示提醒。

增加防重复提醒机制，避免连续点击产生大量重复通知。

### 2. 车员端

地址状态包括：
- 待填写
- 已提交
- 逾期未提交

车员可以查看自己当前车次的地址状态。

地址收集期间，允许修改已经提交的地址。

## 七、模块五：到货检查

当车主收到国际包裹后，可以：

1. 将物流状态更新为「车主已签收」。
2. 检查商品。
3. 点击「确认到货检查完成」。

点击确认后：
- 当前车次进入国内发货准备阶段。
- 普通地址收集阶段结束。
- 未提交地址的车员标记为「逾期未提交」。
- 车主仍可向未提交地址的车员发送催促提醒。
- 未提交地址的车员仍可通过逾期补交入口提交地址。

已经提交地址的车员，可以查看自己的地址信息。

如果车员在打包或发货前需要修改地址，应允许修改；已经发货的订单不允许直接修改收货地址。

## 八、模块六：国内发货管理

### 1. 车主端

在车次物流管理页面增加「国内发货」模块。

展示所有已确认车员及其发货状态。

车主可以针对每位车员单独录入：
- 国内快递公司
- 国内快递单号
- 发货时间
- 发货备注（可选）

国内发货状态包括：
- 待填写地址
- 待打包
- 待发货
- 已发货
- 已签收

车主录入物流公司和快递单号后，可以将对应车员标记为「已发货」。

已发货的车员自动收到站内通知。

未提交有效收货地址的车员不能被标记为已发货。

### 2. 车员端

在「我的拼车」中新增「查看物流」入口。

进入后可以看到：

国际物流：
- 整辆车共享的物流信息和运输进度。

国内物流：
- 自己的快递公司。
- 自己的快递单号。
- 发货时间。
- 当前发货状态。

车员只能查看自己的国内物流信息，不得查看其他车员的个人收货地址或快递单号。

### 3. 数据同步

车主修改某位车员的国内物流信息后：

- 立即更新对应车员的个人订单数据。
- 刷新页面后仍然保留。
- 不得影响其他车员的物流记录。

模拟阶段不需要真实快递查询接口。

「已签收」状态可以由车主手动更新，不要伪装成真实物流公司自动同步。

## 九、站内通知

沿用现有通知机制；如果没有通知模块，则增加一个简单的站内通知入口。

通知类型：
1. 国际物流开始，提醒补充地址。
2. 车主催促填写地址。
3. 车主确认到货检查完成。
4. 车主已为当前车员发货。

通知应包含：
- 通知标题
- 通知内容
- 关联车次
- 创建时间
- 已读 / 未读状态

点击通知可以进入对应车次的相关页面。

不需要短信、邮件或微信通知。

## 十、数据与权限要求

请在现有数据结构基础上，按需增加：

- SavedAddress：用户地址簿。
- OrderShippingAddress：当前拼车订单的收货地址快照。
- InternationalShipment：车次共享国际物流。
- DomesticShipment：车员个人国内物流。
- Notification：站内通知。

要求：
- 一个车次对应一份共享国际物流。
- 一个车员在同一车次对应一份收货地址记录。
- 一个车员在同一车次对应一份国内发货记录。
- 同一车次不同车员的国内物流数据相互独立。
- 数据必须与现有车次 ID 和用户 ID 正确关联。
- 不得破坏已有的拼车、模拟付款、成团及群聊数据。

如项目仍使用 localStorage 和模拟身份，请明确标注这些权限仅用于本地演示，不构成真实的数据隔离或安全保护。

演示数据请使用虚构的姓名、电话和地址，不要求用户输入真实个人信息。

## 十二、功能验收标准

完成后必须能够演示以下流程：

1. 用户在个人中心新增两个常用地址，并设置默认地址。
2. 车主进入已经拼成的车次，录入国际物流信息。
3. 车主将状态更新为国际运输中。
4. 车员收到补充地址通知。
5. 车员从地址簿选择一个地址并提交。
6. 另一名车员填写临时地址，并选择保存到地址簿。
7. 车主看到地址收集人数和提交状态变化。
8. 车主向未提交地址的车员发送催促通知。
9. 车主确认收到国际包裹并完成检查。
10. 逾期未提交地址的车员仍可补交。
11. 车主为不同车员分别填写国内快递公司和单号。
12. 车员只能在自己的账号中查看自己的国内物流。
13. 修改个人地址簿不会影响已提交的订单地址。
14. 刷新页面后所有数据仍然存在。
15. 原有拼车、付款、成团和群聊流程仍然正常。
